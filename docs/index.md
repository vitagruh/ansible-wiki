# Ansible в администрировании и кибербезопасности

Практическая вики для распределённой филиальной сети, где управляемые машины размещены на собственных хостах VMware ESXi. Материал охватывает путь от первого безопасного playbook до централизованной автоматизации, харденинга по CIS/STIG и автоматизации реагирования на инциденты.

**Среда по умолчанию:** 200–1000 управляемых хостов; RHEL/Rocky/AlmaLinux 8–9, Ubuntu 22.04/24.04, Debian 12; сетевые устройства и Kubernetes on-prem; ansible-core 2.17+. Windows Server/AD и публичные облака — опциональные расширения.

## Для кого эта вики

- **Системный администратор** — освоить Ansible с нуля и автоматизировать рутину в филиалах.
- **Security engineer / SecOps** — внедрить харденинг, контроль дрейфа, управление патчами и доказательства соответствия.
- **SOC-инженер** — использовать Event-Driven Ansible и playbook-реагирование с предохранителями.
- **Архитектор** — выбрать стек, спроектировать управление филиалами и виртуализацией, выстроить governance.
- **Руководитель ИБ** — понять этапы внедрения, метрики и риски.

## Что охватывает

1. **Основы и архитектура** — agentless-модель, inventory, переменные, playbooks, roles, collections, Execution Environments.
2. **Безопасная разработка автоматизации** — модель угроз, секреты, доступ, supply chain, аудит запусков.
3. **Администрирование** — филиалы и WAN, Linux, VMware ESXi/vCenter, сеть, Kubernetes, бэкапы, масштабирование, миграция.
4. **Кибербезопасность** — харденинг Linux и ESXi, SSH/PAM, firewall, аудит, PKI, логирование, патчи, комплаенс, реагирование на инциденты, EDA, zero trust, air-gapped.
5. **Качество** — тестирование, CI/CD и GitOps, ревью и релизы, AAP/AWX/Semaphore, governance, обучение.
6. **Эксплуатация** — troubleshooting, чек-листы, анти-паттерны, дорожная карта, FAQ, шпаргалки, источники.

## Конвенции

- **Только защитные практики.** Никаких оффенсивных техник; упор на харденинг, контроль и реагирование.
- **Проверяемые версии.** Baseline — ansible-core 2.17+; при различиях поведения указывается версия. На RHEL 8 для управляемых узлов нужен python39: поддержка Python 3.6 прекращена с 2.17.
- **Запускаемые примеры.** FQCN, идемпотентность, `validate` для конфигов, проверка результата.
- **Безопасные изменения.** Для firewall, SSH, sudo и сети — сначала `--check --diff`, затем canary через `serial`, затем полная раскатка; у каждого риска указан откат.
- **Секреты не в коде.** Только `ansible-vault`, внешние хранилища или credentials платформы; в примерах — заглушки.
- **Единая терминология.** Термины фиксируются в [глоссарии](start/glossary.md).

## Как пользоваться примерами

1. Проверьте версии ansible-core, Python и коллекций; установите зависимости из `requirements.yml`.
2. Запустите пример в лаборатории или на одном тестовом хосте.
3. Выполните `ansible-playbook --check --diff` и изучите планируемые изменения.
4. Примените на канареечном хосте (`serial: 1`), проверьте результат и логи.
5. Расширяйте раскатку по филиалам, контролируя blast radius и имея план отката.

## Границы

- Windows Server/AD и публичные облака — не входят в базовую поставку; добавляются отдельными страницами по запросу.
- Коммерческие SIEM/EDR не настраиваются детально; рассматривается интеграция через Ansible.
- Конкретные национальные требования зависят от юрисдикции и фиксируются плейсхолдерами до уточнения.
