# Ansible в администрировании и кибербезопасности

Практическая вики для распределённой филиальной сети: 200–1000 управляемых хостов на собственных VMware ESXi, RHEL/Rocky/AlmaLinux 8–9, Ubuntu 22.04/24.04, Debian 12, ansible-core 2.17+.

Материал охватывает путь от первого безопасного playbook до централизованной автоматизации, харденинга по CIS/STIG и автоматизации реагирования на инциденты. Только защитные практики: без оффенсивных техник, эксплуатации уязвимостей и обхода защиты.

## Локальная сборка

Требуется Python 3.10–3.13 и MkDocs Material. Python 3.14/3.15 поддерживается не всеми зависимостями: PyYAML пока не публикует wheel для этих версий, и установка может потребовать компилятор.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install -r requirements-docs.txt
mkdocs serve
```

Сборка с проверкой строгих ссылок и навигации:

```bash
mkdocs build --strict
```

## Проверка содержимого

```bash
python tools/verify_docs.py
```

Скрипт проверяет frontmatter, один H1, парность code fences, локальные ссылки, уникальность slug и наличие обязательных разделов. Код возврата `1` означает, что есть ошибки.

## Экспорт в BookStack

```bash
python tools/build_bookstack.py
```

Результат — `dist/ansible-wiki-bookstack.zip` в формате BookStack Portable ZIP: книга, главы и страницы с markdown-контентом. Импорт выполняется в BookStack через **Books → Import** или `/import`; требуется право «Import content». Относительные ссылки между страницами преобразуются во внутренние ссылки BookStack.

## Правила контента

- Только defensive security: харденинг, контроль, обнаружение, реагирование, комплаенс.
- Секреты не хранятся в коде и примерах; используются `ansible-vault`, внешние хранилища или credentials платформы.
- Примеры полные, с FQCN, идемпотентностью и проверкой результата.
- Для рискованных изменений: `--check --diff`, canary через `serial`, план отката.
- Версии и поведение сверяются с официальной документацией Ansible, VMware и стандартов.
